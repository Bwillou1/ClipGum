1. Threat Model & Local Confinement

Traditional clipboard managers store an unencrypted SQLite history of everything copied (passwords, tokens, private chats), creating a massive honeypot for infostealer malware. ClipGum inverts this model: zero persistent storage, processing strictly triggered on paste demand.

Zero-Persistence Architecture: When you copy a token or password, ClipGum never writes to NVMe SSD disk, log files, or databases. All filtering occurs strictly inside volatile process RAM.
Risk Vector ClipGum Mitigation Architecture Status
Remote exfiltration over network No outbound network sockets are ever created for data processing. Bonsai 4B MLX executes entirely on-device. Mitigated by Design
Theft of disk-persisted clipboard DB ClipGum does not maintain any database or disk cache of clipboard items. Non-existent Vector
Unauthorized process memory snooping macOS Hardened Runtime, App Sandbox compliance, Apple System Integrity Protection (SIP). Apple Certified
Accidental leakage of team API keys Deterministic high-entropy regex engine (AWS, GitHub, Stripe, JWT tokens automatically redacted). Active by Default

2. Zero-Network Air-Gap Guarantee

ClipGum operates without any tracking infrastructure. There are no telemetry pings, crash reporting endpoints, or user analytics SDKs (no Google Analytics, Mixpanel, or Segment).

The software is fully compatible with strictly air-gapped workstations in defense, finance, and medical sectors. You can monitor ClipGum using packet inspection tools such as Little Snitch or Wireshark: zero packets are transmitted during sanitization or inference.

3. Clipboard Data Lifecycle

  1. Explicit User Invocation: ClipGum only inspects clipboard content when triggered via hotkey (⌘⇧V or radial wheel ⌘⌥V). No background clipboard spying.
  2. Ephemeral RAM Processing: Text is filtered (removing UTM query params, masking secrets, converting tables, or running MLX inference).
  3. Target Application Injection: Purified content is returned to the clipboard and pasted.
  4. Instant Eviction: Swift memory buffers are deallocated immediately by Automatic Reference Counting (ARC).

4. GDPR, HIPAA & PCI-DSS Compliance

4.1 General Data Protection Regulation (GDPR - EU 2016/679)

Under GDPR Article 4, ClipGum acts neither as a Data Controller nor as a Data Processor, as no personal data is ever collected, stored, or transferred to third parties.

  • Data Minimization (Art. 5.1.c): Fulfilled to the maximum degree possible: 0 bytes retained.
  • Privacy by Design & Default (Art. 25): Ephemeral execution model built into core architecture.
  • International Transfers (Art. 44+): Not applicable as zero cross-border data transfer occurs.

4.2 HIPAA & Protected Health Information (PHI)

ClipGum is not a Covered Entity or Business Associate under HIPAA. Utilizing ClipGum on hospital workstations to clean medical clinical notes or patient IDs creates zero HIPAA violation exposure since no cloud transit occurs.

4.3 PCI-DSS (Payment Card Security)

ClipGum includes built-in Luhn algorithm verification to automatically mask inadvertent credit card numbers before pasting into Slack, support tickets, or issue trackers.

5. Apple Silicon Hardware Encryption

On Apple Silicon Macs (M1, M2, M3, M4), ClipGum benefits from native hardware-enforced silicon security:

  • Inline Memory Encryption: Unified LPDDR5 RAM is automatically encrypted in hardware by Apple Secure Enclave.
  • Pointer Authentication Codes (PAC): Prevents memory corruption, ROP/JOP attacks, and buffer overruns.
  • Apple MLX Direct NPU Acceleration: Model weights for Bonsai 4B MLX stay securely confined within unified memory.
