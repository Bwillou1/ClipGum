# ClipGum custom rules and plugins

ClipGum 1.0 supports two kinds of local, explicitly invoked rules:

- **Regular expressions**: an `NSRegularExpression` pattern and an optional replacement template.
- **Boop-compatible JavaScript**: a self-contained script exporting `main(input)` and returning a string.

Rules are never run at launch, on clipboard changes, or on a timer. A rule runs only when you select **Test Selected Rule** in Preferences or choose a transformation that explicitly includes it.

## JavaScript format

```javascript
function main(input) {
  return input.trim();
}
```

The input is one UTF-8 string. The return value must be one string. ClipGum does not inject Boop's `ScriptExecution`, `require`, or any other host object. Existing Boop scripts that depend on filesystem modules, `ScriptExecution`, network access, or native bridges must be rewritten as pure functions.

## Air-gap and resource boundaries

The JavaScriptCore context contains only standard JavaScript built-ins and the single input argument. There is no filesystem, network, environment-variable, process, AppleEvent, or pasteboard bridge. Common host names are explicitly shadowed before source evaluation. Imported scripts are parsed and checksummed but are not executed during import.

Each invocation has:

- a **250 ms native JavaScriptCore context-group execution cutoff**;
- a **16 MiB resident-growth budget**, checked by the watchdog and after evaluation;
- 64 KiB maximum source, 2 MiB maximum input, and 2 MiB maximum output;
- a fail-closed error if the system does not export the native execution watchdog.

The memory figure is a process resident-growth guard, not a claim that Apple exposes a separate JavaScriptCore heap allocator limit. A script error is shown as a safe error code/message; source, input, output, regex tokens, and session mappings are not sent to logs or diagnostics.

## Rule packs

Preferences → **Rules** imports and exports JSON packs. A pack has `schemaVersion`, an ordered `rules` array, and a SHA-256 `checksum` over the canonical versioned payload. Import validates the checksum, schema, unique IDs, names, source limits, and regular-expression syntax before saving. Duplicate IDs replace the existing rule only after the complete pack validates.

Example shape (the checksum is generated by ClipGum):

```json
{
  "schemaVersion": 1,
  "rules": [
    {
      "id": "7D8D8B6D-4D6B-4D8F-9D64-3F4A2C0A6E11",
      "name": "Trim",
      "kind": "script",
      "source": "function main(input) { return input.trim(); }",
      "replacement": "",
      "isEnabled": true
    }
  ],
  "checksum": "generated-sha256-hex"
}
```

## Encrypted configuration backups

Preferences → **Rules** also imports/exports password-protected `.clipgum`
archives. The archive uses Argon2id (version 1.3, bounded parameters) to derive
an AES-256 key and AES-GCM with the complete binary header as authenticated
associated data. Each export gets a fresh random salt and nonce. Wrong passwords,
modified headers/ciphertext, unknown schema fields, excessive KDF parameters,
and oversized archives fail closed.

The payload is an allow-listed configuration schema containing custom rules and
bounded preferences only. Clipboard text, pasteboard flavors, clipboard history,
Share-Ready mappings, device private keys, and session keys have no fields in
that schema. Export performs an audit before writing; import repeats the audit
before decoding and never executes imported scripts. Model paths are not
automatically loaded after import, and managed telemetry/script restrictions
still take precedence.

Argon2 Swift is pinned and its MIT license is included in the application's
license resources. Backup operations are explicit file-panel actions; no
background backup or cloud upload exists.

## Enterprise controls

An administrator can set `DisableCustomScripts` to prevent JavaScript rules from being added, enabled, or tested. Regex rules remain available. `ForceSecretRedaction` is applied again at the final copy/paste boundary, even if a rule produced the text.

## Development references

The pure-function shape follows the public Boop script model (`main(input)`), while the native watchdog uses the exported JavaScriptCore context-group limit pattern also used by open-source Swift watchdog implementations. ClipGum does not claim to have inspected proprietary Raycast extension source.
